| `dist/migrate.js` + `migrate.d.ts` · `dist/migrate-data.js` | `fromLucide`, `fromHeroicons`, `fromSFSymbol` and `maps` (copied from `engine/migrate.mjs`), and the maps of `src/migrate/` as checked by `load.mjs` ([migration](#migration-srcmigrate-flouviagotamigrate-gota-migrate)) |
| `dist/search.js` + `search.d.ts` · `dist/search-core.js` · `dist/search-data.js` | `searchIcons` (from `engine/search-api.mjs`), the search engine (copied from `engine/search.mjs`), and the generated index data: category, tags, labels, and keywords per icon |
| `dist/motion.css` · `dist/motion-css.js` | The animations from `engine/motion.css`, as a stylesheet and as text for the components to inject |

With `--check <category>` it only validates (agents use it while drawing). The build rewrites `dist/` except what other scripts write there: `fonts/` (`font.mjs`) and `android/`, `xcode/`, `figma/` (`native.mjs`) stay until their own script runs again, so a build never takes away the Figma plugin someone has imported.

**The hand-drawn variant wins:** if `<name>-circle`, `-square`, `-slash`, or `-off` exists as an icon of its own, the build doesn't generate the automatic one with that name, and every API draws the drawn one instead: each icon's data links it (`drawn`, in `icons/<name>.js` and `iconData`) and `pick` follows the link (`svg`, `toSvg`, and every component); `resolveIcon` does the same by name (the MCP server).

## Outlines (`scripts/outline.mjs`)
Android vector drawables, Xcode symbols, and icon fonts can't hold strokes or masks, so they get each icon as filled shapes: `outline(icon, options)` returns one `d` (nonzero) in the 24 canvas for any of `render`'s options. It needs the dev dependency `canvaskit-wasm` (Skia).
- **One source of truth:** it doesn't redraw the icon; it evaluates `render`'s own SVG with Skia's path operations. Every fill and stroke is a region (with its width, caps, and joins); later paint covers earlier paint; inside a mask white keeps and black clears; a group is painted on a layer of its own, cut by its mask, and moved by its transform.
- **Holes turn against their outline:** each contour is rewound by its depth (how many others contain it), so the result fills the same with the nonzero rule (fonts) and the even-odd rule.
- **Checked, every time:** Skia also rasterizes the SVG as a browser does (masks by luminance) and the outline at 96 px. Scattered edge pixels are antialiasing; a clump of six or more is a loss (a dot is ~28). On a mismatch it joins the pieces another way (all at once, in a chain, in reverse, laid over each other without a union, nudged by thousandths of a unit); if none matches, it throws, naming the icon. A wrong outline never ships. To diagnose one, `attempts(svg)` returns what each way gives and how far it is from the drawing.
- **Measured** (22 Oct 2026): the 1,033 icons in ten variants (outline, fill, slash, circle, filled square, weights 0.75 and 2.6, 16 px outline and fill, mirrored), 9,573 outlines in 46 s, all matching. The check found one real defect, in the engine: `sq` corners that didn't fit their side made it run backwards (25 icons, [decision 52](./decisions.md#phase-2-22-oct-2026)).

## Compatible masters (`scripts/masters.mjs`)
A variable font and an Xcode variable symbol interpolate between masters, so the masters must share their structure point for point. `masters(icon, options, [0.9, 1.5, 2.1])` returns each weight's outline with the same contours, segments, and commands:
- each weight's checked outline (with unions first; then with the pieces laid over each other); invisible slivers (under 0.02 of area) are left out;
- contours paired across weights by turn, nesting depth, center, box, and spread (second moments, which tell apart orbits that share a center);
- points made to correspond, trying four ways in turn and keeping the first whose result passes every check: **following the regular master** (stations along it, its sharp corners among them, carried to each master by nearest point, searching forward, so a round cap maps radially onto the wider or narrower cap); **anchored** (the corners every master shares as anchors, following in between, where following alone jumps between close branches near a cut's corners); **each contour its own way** (the first of those that traces that contour faithfully in every master); and **corners and fractions of length**;
- each piece drawn as a quadratic curve (TrueType's own), split in all masters at once wherever one of them strays more than 0.02 (0.02 px at 24 px), and a point that lies on a straight run in every master dropped, in every master at once;
- every master checked against its drawing, and the outline halfway between masters (interpolated) checked against the drawing at that weight, as strictly as the masters: a failed check says where (`where`, the box of the largest mismatch).

Measured on 22 Oct 2026: 1,853 of the 1,865 outline and fill variants (99.4 %) have compatible masters, and every icon keeps its structure from 0.9 to 2.1. The other 12 interpolate with a visible error where a cut or a join moves nonlinearly (a bump where a badge's clearance meets a curve, a flattened cap): masters work, not drawing. `describe` and `between` (by any of the four ways) are there to diagnose one.

## Icon fonts (`node scripts/font.mjs`)
After the build; it needs `npm ci` (Skia). Written by `scripts/sfnt.mjs`, with no dependencies: TrueType outlines (quadratic, as the masters are), `cmap` 4 and 12, a ligature `GSUB`, `fvar`, `gvar`, and `STAT`, and WOFF2 (brotli; `glyf` and `loca` untransformed, which the format allows).
| File | What it holds |
|---|---|
| `dist/fonts/gota.woff2` · `gota-fill.woff2` (and `.ttf`) | Variable: a weight axis from 300 (Light, 0.9) to 700 (Bold, 2.1), 400 Regular (1.5), as `weight="auto"` maps a text's weight, from the compatible masters |
| `dist/fonts/gota-{light,regular,bold}[-fill].woff2` (and `.ttf`) | Static, each master as it is (300 · 400 · 700) |
| `dist/fonts/gota.css` · `codepoints.json` | The `@font-face` rules and the `.gota` and `.gota-fill` classes; each icon's codepoint |

- **Codepoints** are stable, in the Supplementary Private Use Area-A (from U+F0000: the BMP's 6,400 wouldn't hold 10,000 icons): `src/codepoints.json` is committed, a new icon gets the next one, and a codepoint is never given to another icon.
- **Ligatures:** an icon's name typed as text becomes the icon; the letters themselves are empty and zero wide.
- **Grid:** 4,800 units per em (200 per canvas unit), the 24 canvas filling the em from the baseline up; points within 0.0025, so rounding never tips an interpolated weight past the check.
- **An icon without compatible masters** keeps its regular drawing at every weight of the variable font (6 per style, reported); the static fonts have every icon at its own weight.
- **Checked twice:** the glyphs are read back from the bytes written by an independent reader, the variable ones interpolated as a rasterizer does, and compared with `render()` at 300, 350, 400, 550, and 700 by Skia (the masters' own check); then Chrome loads every font (its sanitizer rejects a malformed table), every name must form its ligature, and every varying glyph must change between 300 and 700. Chrome's text rasterizer isn't the judge of the drawing: it snaps the baseline to the pixel and, on macOS, thickens text.
- Measured on 22 Oct 2026 (1,033 icons): `gota.woff2` 581 KB, `gota-fill.woff2` 483 KB, `gota-regular.woff2` 244 KB; 2 min 20 s.

## Native formats (`node scripts/native.mjs <format>`)
From the checked outlines, after `scripts/build.mjs`; it needs `npm ci` (Skia).
| Format | Output |
|---|---|
| `xcode` | `dist/xcode/Gota.xcassets/<name>[.fill].symbolset`: Xcode custom symbols, variable templates (below) |
| `android` | `dist/android/<light\|regular\|bold>/<outline\|fill>/gota_<name>[_circle\|_square\|_slash].xml`: Android vector drawables, the same matrix as `dist/svg` (20,088 files for 1,033 icons). One path, nonzero, `android:tint="?attr/colorControlNormal"` with a white fill so the theme colors it, and `android:autoMirrored` on directional icons |
| `figma` | `dist/figma/` (`manifest.json`, `code.js`, `ui.html`): a development plugin that builds Gota's Figma library (below), and `cover.png`, the file's cover |

Path data is compact: absolute coordinates rounded to hundredths first (0.005 at most), then written relative to the previous rounded point so rounding never adds up along a contour; lowercase commands, implied repeats, h/v for straight lines. The check runs on the compact data, so what is checked is what ships. Android for 1,033 icons: 41 MB, 19 MB zipped (40 % less than plain Skia output).

**Xcode** (`xcode`, macOS with Xcode): `dist/xcode/Gota.xcassets`, one symbol image set per icon and style (`bell`, `bell.fill`; 1,865), used with `Image("bell")` or `NSImage(named:)`. Each is a variable template ([decision 68](./decisions.md#weights-22-oct-2026)): the icon's three masters as Ultralight, Regular, and Black (quadratics written as the cubics they are), the 24 canvas typeset at 100 pt and centered on the cap height, its margins at the canvas's edges; Xcode draws every other weight and the three scales between them. Every template is compiled by `actool` (no warning allowed) and every symbol drawn by AppKit at Ultralight, Regular, and Black: it must load and change from the lightest to the heaviest. An icon without compatible masters has its regular drawing in all three (12, reported). A static template was probed first and rejected: Xcode doesn't interpolate one, and every missing weight or scale falls back to Regular-M as drawn. 5 min; `Assets.car` 25.7 MB.

**Figma** (`figma`; [decision 73](./decisions.md#outputs-23-oct-2026)): the plugin in `scripts/figma/` (`code.js` for Figma's sandbox, in plain ES2017; `ui.html`, its panel) with the icons packed into the panel (JSON, gzip, base64: 4.9 MB). In the open file it builds one page per category (the core set first) and one component set per icon, named like the icon, with two variant properties: **Style** (Outline, Fill) and **Weight** (Light, Regular, Bold), 6,198 variants for 1,033 icons. Each variant is a 24 × 24 component with one vector, `Icon`, that scales with it: the icon's outline at that weight, written as absolute `M`, `L`, `Q`, `C`, `Z` (the only path syntax Figma takes; `absolute()` in `scripts/outline.mjs`) and checked again as written. A set's description carries the English and Spanish labels and every keyword, so Figma's asset search finds icons by meaning. Running it again updates in place: each vector is redrawn, so components keep their keys and instances in other files keep their overrides; a set whose icon left Gota is listed, never deleted. 1 min to write.
- **Use:** in Figma's desktop app, *Plugins → Development → Import plugin from manifest…* → `dist/figma/manifest.json`, then run *Gota library* in the file that will be the library (a new one the first time; later runs, in that same file). Publishing it as a team library is the owner's step; the Community file waits for v1.
- Tested against a stand-in for Figma's API (`tests/figma.test.mjs`); the first run in Figma itself is the owner's.
- **The cover** (`dist/figma/cover.png`, 1920 × 1080, from `scripts/figma/cover.mjs`, drawn in Chrome): the set as a quiet field on Flouvia's graphite (`#161617`), its weight growing from Light at the left to Bold at the right and fading to the edges, around a clearing with only "Gota" and Flouvia's logo, both Flouvia's and read from the private sibling repository when the cover is drawn (`../flouvia`: the logo for dark backgrounds, and "Gota" in Flouvia Sans as outlines); nothing of Flouvia's brand is kept in this repository. Without that folder the name is set in Helvetica Neue and the logo is left out. In Figma: a "Cover" page first, the image in a frame of its size, *Set as thumbnail*; it is also the Community thumbnail at v1.


## Typefaces (`node scripts/type.mjs <folder>`)
Typefaces drawn with the engine, the way icons are ([decision 77](./decisions.md#outputs-23-oct-2026)): a folder holds the source, `glyphs.mjs` (a function that receives the engine's primitives, `arc`, `circ`, `drop`, `line`, `dot`, and returns the typeface: family, metrics in canvas units, each glyph's stroke axes with its width and side bearings, the marks, the accented letters composed from them, and the words to write as outlines), and its `LICENSE`. The tool writes, in that folder:
- `fonts/<Family>[wght].ttf · .woff2` (variable, weight 300–700, Gota's 0.9 to 2.1 stroke) and `<Family>-{Light,Regular,Bold}.ttf · .woff2`, with `<family>.css`;
- `words/<word>-{light,regular,bold}.svg`: the words as outlines (a logo's name), the baseline at y = 0;
- `specimen.png`, set in the fonts just written, by Chrome (`--no-specimen` skips it).

Each glyph is an icon to the engine: its strokes on the 24 canvas (its origin at (4, 19), room for capital accents and descenders at the boldest weight), outlined at the three weights as compatible masters (`scripts/masters.mjs`, each checked against the drawing); one without them keeps its regular outline across the variable font, reported. Vertical metrics, Unicode ranges, the embedding flag (restricted, `fsType` 2), and the names table (copyright, trademark, manufacturer, license and its URL) come from the source. `scripts/contours.mjs` turns path data into TrueType contours for both the icon fonts and typefaces. No typeface's design lives in this repository: Flouvia's (Flouvia Sans) is in the private `flouvia-web`, under its own license, and is built from there (`npm run brand:type`).

## Migration (`src/migrate/`, `@flouvia/gota/migrate`, `gota-migrate`)
For moving a codebase to Gota from Lucide, Heroicons, or SF Symbols ([decision 75](./decisions.md#outputs-23-oct-2026)).
- **The maps** (`src/migrate/lucide.json`, `heroicons.json`, `sf-symbols.json`): data, one entry per name of the other set that Gota shows the same way, and nothing for the rest. A value is a Gota name, or `{ name, enclosure?, slash? }` (Lucide and Heroicons: `circle-chevrons-left` is `chevrons-left` in a circle). SF Symbols maps *concepts*: a name without its suffixes, which become variants when it is read (`.fill` → fill, `.circle`/`.square` → enclosure, `.slash`), so `bell` covers `bell.slash.circle.fill`; a name the map holds whole wins over its concept (`info.circle` → `info`, whose circle is part of its drawing). `load.mjs` checks every entry: an icon that exists, an enclosure or slash it can take. Today: Lucide 973 of its 1,903 icons, plus 184 of its old names still exported (1,157 entries); Heroicons 285 of 324; SF Symbols 708 entries covering 1,814 of its 8,091 names (localized glyphs aside). They grow with the set (phase 3).
- **How they were made:** each name was judged by meaning by agents that compared the drawings (precision over coverage: same object, same state, same direction and count, or nothing), then checked by Claude on review sheets with each original beside its Gota equivalent (SF Symbols drawn by AppKit). The other sets' files are read only to make and check the maps; nothing of theirs is committed.
- **`@flouvia/gota/migrate`:** `fromLucide(name)`, `fromHeroicons(name, { style })` (`solid` is Gota's fill), `fromSFSymbol(name)` → `{ name, variant?, enclosure?, slash? }`, the props of Gota's components, or `null`. They take a set's own names or its component names (`CircleCheck`, `LucideBellOff`, `CheckCircleIcon`); an SF name with an enclosure or slash its icon can't take is `null`.
- **`gota-migrate`** (`migrate/cli.mjs`, transforms in `migrate/transform.mjs`, no dependencies): `npx -p @flouvia/gota gota-migrate [paths…]` shows every change and note; `--write` applies them. It skips `node_modules`, `.git`, build outputs, `Pods`, and `DerivedData`.
  - JS, TS, JSX, Vue, and Astro: named imports from `lucide-react`, `lucide-vue-next`, `@heroicons/react/{24/outline,24/solid,20/solid,16/solid}`, and `@heroicons/vue/…` become `@flouvia/gota/react/icons` or `/vue/icons` under the same local names (`BellIcon as Bell`), so the code that uses them doesn't change. Every tag (JSX, or a Vue template in either case) gets the props its equivalent needs; Lucide's `strokeWidth` becomes a named weight (≤ 1.5 light, 2 regular, ≥ 2.5 bold) and `absoluteStrokeWidth` goes.
  - Swift: `Image(systemName:)`, `UIImage(systemName:)`, `NSImage(systemSymbolName:accessibilityDescription:)`, and `Label(_:systemImage:)` take Gota's Xcode symbols by name (`bell.slash.fill` → `"bell-off.fill"`: the drawn variant and the fill symbol when there is one).
  - What it can't carry over safely stays as it was, with a note: an icon with no equivalent yet, an icon used as a value (its props can't follow it), a stroke width that isn't a number, an import it doesn't read (a namespace, a default, a deep path), an SF name that isn't a literal or whose enclosure exists only in code.
- **For agents:** the MCP server's `find_equivalent` (below) answers with the same maps.

## Publishing (once there are 10,000)
- **npm:** `@flouvia/gota` with `dist/`, `svg/`, `mcp/`, `migrate/`, `LICENSE`, `README.md`, and `README.es.md` (`files` in `package.json`). Exports: `.`, `./core`, `./icons`, `./icons/*`, `./react`, `./react/icons`, `./vue`, `./vue/icons`, `./svelte`, `./svelte/base`, `./astro`, `./morph`, `./search`, `./migrate`, `./sprite.svg`, `./sprite-fill.svg`, `./svg/*`, `./icons.json`, `./icons.css`, `./motion.css`, `./font.css`, `./fonts/*` (the WOFF2 fonts; the TTFs, for desktop apps, go in the release ZIP, not in the package). `sideEffects` lists only the stylesheets, so bundlers drop every module a page doesn't use. React, Vue, and Svelte are optional peer dependencies; the package itself has none. Binaries: `gota-mcp` and `gota-migrate`.

- **GitHub Releases:** a GitHub Action, when a version is tagged, runs the build and attaches a ZIP with the SVGs sorted by weight and style, the fonts as TTF, the Android vector drawables, and the Xcode asset catalog (none of them in the npm package).
- Semantic versioning, a changelog, and aliases for renames ([decisions](./decisions.md)).
- Site: `gota.flouvia.com` ([roadmap](./roadmap.md)).

## MCP server (`mcp/`, `api/mcp.mjs`)
Lets AI agents (Claude Code, Cursor, Claude Desktop…) find icons by meaning and insert the exact SVG or component code. No dependencies. `mcp/handler.mjs` holds the tools and the JSON-RPC 2.0 dispatch (`initialize`, `ping`, `tools/list`, `tools/call`; one message or a batch); two transports only move messages:
- **Local, over stdio** (`mcp/server.mjs`, the `gota-mcp` binary): one message per line. `node mcp/server.mjs` in the repo, after the build, or `npx -p @flouvia/gota gota-mcp` once published.
- **Remote, over HTTP** (`api/mcp.mjs`): `https://gota.flouvia.com/mcp` ([decision 71](./decisions.md#outputs-23-oct-2026)). MCP's Streamable HTTP, stateless: a POST of JSON-RPC gets its answers as `application/json`; notifications get `202`; no sessions and no event stream, so `GET` and `DELETE` answer `405`. It checks `Content-Type` (415), `MCP-Protocol-Version` (400 for a version it doesn't speak), and the body's size (64 KB, 413). Public and read-only: any origin (CORS `*`), no credentials, `Cache-Control: no-store`. In Claude Code: `claude mcp add --transport http gota https://gota.flouvia.com/mcp`.

Versions: a client asking for 2024-11-05, 2025-03-26, 2025-06-18, or 2025-11-25 gets it back; any other gets the newest. Every tool is marked read-only (`annotations`).
| Tool | What it returns |
|---|---|
| `search_icons { query, limit?, category? }` | Names, labels, and categories, best first ([search](./engine.md#search-enginesearchmjs)); 12 by default, 50 at most |
| `get_icon { name, format?, variant?, weight?, enclosure?, slash?, size?, animate?, play? }` | `format`: `svg` (default), `react` (the `<Icon>` line and its import), or `data`. An unknown name gets suggestions |
| `list_categories {}` | The categories and how many icons each has |
| `find_equivalent { from, name, style? }` | `from`: `lucide`, `heroicons`, or `sf-symbols`. The Gota icon that shows the same thing, with its props, its React line and (SF Symbols) its Xcode symbol; with none, nearby icons to check ([migration](#migration-srcmigrate-flouviagotamigrate-gota-migrate)) |

A tool's bad input (no query, an unknown icon, an option the engine rejects) comes back as a tool result with `isError`, which the model reads and corrects; an unknown tool is a JSON-RPC error (`-32602`).

### The remote server's deploy
Vercel project `gota` (team `flouvia`), deployed with the CLI from this folder, linked by `vercel link` (`.vercel/`, not committed). There is no Git remote yet, so a deploy goes out from a clean tree at a commit: `git status --short` empty, then `vercel deploy` (a protected preview, tried with `vercel curl /mcp --deployment <url>`) and `vercel deploy --prod`.
- `vercel.json`: no dependencies to install (`npm ci --omit=dev`), the build (`node scripts/build.mjs`, which writes the `dist/` the function imports), the function with `dist/icons.json` and `package.json` (read from disk, not imported), and the host's routes (below).
- `.vercelignore` uploads only what the build and the function read: `api/`, `engine/`, `mcp/`, `scripts/`, `site/`, `src/`, and the package files.
- `site/`: the host's static files, only `robots.txt` (everything may be indexed but the server).
- **The host, `gota.flouvia.com`** (the `flouvia.com` zone, in Vercel's DNS; [decision 72](./decisions.md#outputs-23-oct-2026)): this project serves `/mcp` itself. Gota's page is built in `flouvia-web` (`flouvia.com/gota` and `/en/gota`, with canonical and hreflang pointing here); once it is live, `/` and `/en` take it by an external rewrite, with its assets, and until then they go to `flouvia.com` (307). Every other path goes to `flouvia.com` (307): the redirects run before the rewrites, so the catch-all leaves out `mcp`, `api/`, `robots.txt`, and, with the page, whatever is proxied.
